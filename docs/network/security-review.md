# Единственный обзор безопасности GPT-6 Astra

Обзор выполнялся на ревизии `8fc18ef`; последующие исправления проверял основной агент без повторного обзора.

Проверена реализация на основе Bitchat Android v2.2.0, включая клиентские транспорты и серверную часть. По решению пользователя выполнен один обзор GPT-6 Astra. После него исправления проверяются локально без второго обзора.

Обзор исходников выявил пять проблем:

| Приоритет | Проблема | Исправление | Локальная проверка |
|---|---|---|---|
| P1 | Плавное закрытие WebSocket может дослать очередь через прежний маршрут | Синхронный `cancel()` всех отслеживаемых сокетов, блокировка публикации нового сокета и эпоха соединения | Проверка отмены без graceful close; существующие проверки поколений маршрута и TLS |
| P1 | Другие действительные реквизиты qWDTT могли присвоить существующий device ID | Проверка владельца до привязки, выдачи конфигурации и регистрации WG/Raw | Реальные обработчики GETCONF/AUTH и GETCONF_RAW/AUTH с разными синтетическими владельцами |
| P2 | Старый Raw допускал повтор захваченной авторизации в другом соединении | Raw v2: случайные nonce клиента/сервера, HMAC-SHA256 взаимного подтверждения, отдельные AES-256-GCM ключи направлений, аутентифицированный счётчик пакетов; старый Raw отклоняется | Рукопожатие, старое подтверждение с новым challenge, повтор и отражение кадров, другой сеанс |
| P2 | Начальный профиль `default` давал одинаковый transport device ID | Отдельный случайный сохраняемый UUID; миграция старых JSON без изменения ссылок на секреты | Разные хранилища получают разные ID; повторное открытие сохраняет ID |
| P2 | Очистка WebView зависела от флага текущего процесса | Удаление cookies и WebStorage без флага, ожидание callback и flush; также при выходе VK | Синтетические cookies удаляются без открытия OAuth Activity |

Raw v2 требует одновременно обновить приложение и сервер qWDTT из этого комплекта. WG и формат сообщений Bitchat не меняются. Не использовать предыдущий Raw-сервер с новым клиентом. Использовать длинный случайный пароль сервера: взаимное подтверждение на основе PSK не защищает слабый пароль от словарного подбора.

Это обзор исходников и локальные регрессионные проверки. Он не заменяет испытания Android native loader, физического mesh, реальных мостов и сервисов, VPS и изоляции трафика на устройстве. Унаследованные криптографические протоколы Bitchat не проходили полный повторный аудит. Проверка не подтверждает отсутствие всех уязвимостей или готовность к производственному выпуску.
