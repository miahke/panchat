# SSH-аутентификация автодеплоера

Продолжение согласованного проекта. В Android реализованы адрес/порт, SSH-логин и выбор пароль / приватный SSH-ключ. Ключ выбирается через системный picker, ограничен 256 КБ, не сохраняется в приложении. Для зашифрованного ключа есть отдельная passphrase. Введённые реквизиты не входят в saved state, экспорт или журналы. Массивы секретов очищаются после попытки подключения и отмены; отображаемые строки удаляются из состояния. JVM/IME могут создавать собственные копии строк: это не гарантия стирания всего содержимого RAM.

Проверенный SHA256 host pin обязателен до сетевой аутентификации. Способ входа задаётся явно: пароль не становится fallback для ключа. Перед установкой проверяются права: UID 0 либо sudo без пароля, заранее предоставленный владельцем. Установщик не меняет sudoers/sshd. Для non-root SFTP использует отдельный временный каталог с правами 0700; там находятся только публичные проверяемые файлы комплекта. Привилегированная установка выполняется через `sudo -n`; пароль не передаётся в sudo. На Android 10 Ed25519 подписи приватного ключа используют BC: одной настройки проверки host key недостаточно, поскольку KeyPair использует глобальную таблицу JSch.

CLI: `--identity` и `--key-passphrase`, либо `--password`. Выбранный ключ передаётся всем SSH/SCP этапам, включая health check. CLI и Android поддерживают произвольный валидный SSH-логин с заранее настроенным sudo без пароля. CLI передаёт публичные файлы фиксированных имён через tar/stdin в привилегированный SSH-процесс; один общий helper обеспечивает pin, identity и sudo на всех этапах.

Проверено локальным синтетическим sshd на loopback: зашифрованный OpenSSH Ed25519, неверная passphrase, неверный pin и путь sudo через управляемый ForceCommand. Это проверка SSH-обмена и сформированных команд; она не подменяет реальную установку под sudo. Проверены границы файла, очистка буферов, валидация логина, отсутствие fallback и quoting. UI-тест проверяет выбор ключа, passphrase и блокировку установки без подтверждённого pin; прежние тесты кнопок проходят. CLI: 9 тестов и Bash syntax.

Полный транспортный автодеплой пока не готов: ядра WG/Raw/Cups уже входят в комплект, но локальная административная служба ещё не связана со всеми путями фактической передачи трафика. Нельзя объявлять выход защищённым только по наличию пароля SSH. Серверный вариант будет использовать необходимые части закреплённых qWDTT/OpenFlux с собственным общим управлением службами и допуском; криптографические протоколы и WireGuard не переписываются заново.

Результат этого этапа: тестовая сборка 2.2.0-transports.7 (48). Полный JVM-набор приложения: 973 теста, 5 opt-in/других пропусков, без ошибок и падений. Отдельный ресурсный UI-прогон: 19 без ошибок/падений. Локальный opt-in SSH-тест с зашифрованным ключом реально выполнен; при обычном запуске он пропускается. CLI: 9 тестов. Release собран успешно. Полный lint и повторный независимый аудит этого SSH-этапа не выполнялись; прежний lint репозитория остаётся с известными ошибками. На боевом VPS новая sudo-ветка ещё не проверялась.
