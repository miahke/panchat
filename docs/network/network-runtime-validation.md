# Сетевые ядра — transports.6

Тестовый выпуск Android 10+ (API 29), четыре ABI: arm64-v8a, armeabi-v7a, x86_64 и x86. Форматы сообщений Bitchat, Noise и Nostr в этом этапе не изменялись.

## Подключение и настройки

Для WG по умолчанию выбран защищённый режим «Авто»: два worker через VK TURN пробуют DTLS/WRAP и RTP AEAD, после подтверждённой конфигурации остаются на выбранном режиме. Оба маршрута проходят через TURN, прямого сетевого fallback к VPS нет. Стандартные порты: DTLS 56000, RTP AEAD 56002, Raw v2 56003. Для нестандартного сервера порты задаются явно. Порт из поля `port` ссылки qwdtt относится к локальному SOCKS, адрес выхода берётся из `peer`.

Перенесены TURN TCP/UDP, bootstrap DNS/DoH, адрес/порт TURN, маскировка audio/video, отдельный DNS туннеля, MTU, таймауты запуска/рукопожатия/получения конфигурации и WG keepalive. Для Cups доступны HTTP/WebSocket timeout, общий timeout, DNS, MTU, keepalive/read timeout, интервалы переподключения и отправки. Противоречивые или выходящие за пределы значения отклоняются до запуска. Два worker — транспортные каналы, а не лимит числа системных потоков.

Статус различает получение TURN, DTLS, конфигурацию VPS, WireGuard/Raw handshake, создание/вход в комнаты и Session handshake. Сырые ошибки, ключи, адреса, хэши и комнаты в журнал состояния не передаются. Состояние восстановления отзывает SOCKS endpoint у клиентов приложения до подтверждённого восстановления.

VK: сначала вход через страницы VK, затем OAuth с одноразовым state и точным HTTPS callback. Обрабатываются callback в query и fragment, включая SPA/history; неоднозначные параметры отклоняются. Нет JS-моста для чтения пароля. Сессия WebView очищается после завершения. Генерация хэшей использует отменяемый POST без токена в URL, устаревший ответ после выхода отбрасывается. Интерактивный вход реальным аккаунтом отдельно не проверялся.

## Единственный обзор Astra и исправления

Отчёт исходного состояния: [astra-network-correctness.md](astra-network-correctness.md). Один завершённый независимый прогон GPT-6 Astra; исправления и повторные тесты выполнял основной агент.

1. Молчание qWDTT больше не продлевается бесконечно. Таймаут чтения завершает worker и запускает переподключение. Обновлённый сервер отвечает на защищённые heartbeat: после первого подтверждения предел молчания 45 секунд. Для legacy WG без heartbeat-ответа предел 180 секунд, с внутренним WG keepalive для подтверждённых rekey. При повторном подключении конфигурация заново запрашивается и проверяется до регистрации worker; одной успешной записи AUTH недостаточно.
2. Raw v2 использует окно из 64 номеров: свежие переставленные записи принимаются, дубликаты и устаревшие записи отбрасываются без закрытия канала. Окно изменяется только после проверки AEAD. Раздельные ключи направлений и случайные nonce рукопожатия сохраняются.
3. Неудачное рукопожатие отдельного Raw worker передаётся как стадия повторной попытки, а не process-level ERROR. Общий бюджет запуска остаётся ограниченным; подтверждённый отказ авторизации при получении конфигурации остаётся фатальным. Plaintext/legacy Raw fallback не добавлялся.
4. Cups Session получает настроенный бюджет запуска вместо скрытого фиксированного ограничения 20 секунд. Отмена прерывает вход в комнаты и ожидание handshake. Стадия handshake поступает до ожидания, а не после успеха. Устранена обнаруженная race в тестовом перенастраивании reorder timeout: буфер фиксирует свой срок при создании.

## Проверки сетевого пути

- Разрешённый тестовый qWDTT: «Авто» выбрал RTP AEAD, подтвердил WG; SOCKS password authentication, DNS внутри туннеля и HTTPS HEAD с обычной проверкой TLS прошли. Полный старт и запрос: около 3,1 секунды в одном измерении; это не гарантия задержки в мобильной сети.
- Повторный запрос после 190 секунд простоя прошёл. Проверка физической смены Wi-Fi/мобильной сети и искусственного blackhole всей цепочки на телефоне остаётся отдельной.
- Cups: живой тест создаёт временные комнаты без аккаунта; зашифрованная Session, локальный SOCKS, отказ неверному паролю, удалённый DNS и HTTPS с проверкой TLS прошли. Ключи генерируются для теста и не сохраняются в исходниках. Это временный тестовый выход, не активация пользовательского VPS.
- Raw v2: синтетический userspace IP → authenticated SOCKS → защищённая Raw-сессия → userspace IP → TCP echo передал синтетический блок текста/голоса/изображения. Проверены неправильный пароль SOCKS, reorder, duplicate, stale, межсессионный replay и отражение между направлениями. Живой Raw на предоставленном внешнем тестовом сервере не согласовал v2; требуется совместимый обновлённый сервер. Этот режим не объявляется проверенным через реальную цепочку VK TURN до VPS.
- Присланный OpenFlux-профиль не декодируется также штатным декодером upstream: повреждён сжатый блок. Комнаты и ключи из него не извлекались и не восстанавливались догадками. Импорт корректных синтетических смешанных профилей проверяется отдельно.

Воспроизведение opt-in Cups: `BITCHAT_CUPS_E2E=1 go test -count=1 -run '^TestLiveCupsEncryptedSocksEgress$' -timeout 4m .` в `native/openflux`. Команда создаёт временные комнаты и делает публичный HTTPS HEAD. Обычные тесты этот сетевой сценарий пропускают.

## Ограничения общего проекта

Аппаратный допуск устройств к передаче VK/Cups, полная миграция идентичности/БД/медиа в парольное хранилище, две редакции и активация рабочих серверных служб остаются незавершёнными. Встроенный деплоер подготавливает сервер, но пока не включает защищённую выдачу доступа ко всему трафику. Нельзя считать открытый legacy-выход защищённым одним наличием административной службы. Реальный VK login, физический mesh/обмен со стоком, Android 10 на устройстве и полный Tor bridge live test данным сетевым этапом не подтверждены.

## Автоматические проверки выпуска

Release APK, Wear debug и штатные контрактные проверки собраны успешно. Полный JVM-набор приложения: 966 тестов, 4 пропущены, без ошибок/падений; Wear: 245 без ошибок/падений. Отдельный ресурсный прогон UI: 18 без ошибок/падений. Go race suites клиента qWDTT, сервера qWDTT, клиента Cups и upstream transport прошли; отдельно прошли новое защищённое Raw SOCKS echo и opt-in живой Cups SOCKS egress. CLI-деплоер: 7 тестов; проверка упаковщика: 5 тестов. Bash-синтаксис установщиков и закреплённые Arti checksums проверены.

Lint не чистый: приложение — 303 ошибки и 412 предупреждений; Wear — 37 и 52 соответственно. Эти значения совпадают с предыдущим этапом. В проверенных `net/route`, `net/vk`, `net/importprofile`, `net/deploy` и `ui/network` ошибок lint нет. Это ограничение общего репозитория, не успешный lint gate.
