# Импорт, удаление подключений и подготовка VPS из Android

Тестовый выпуск 2.2.0-transports.5 (46), продолжение общего сетевого проекта.

## Импорт настроек

Исправлен qWDTT-формат `qwdtt://config`: `peer` может содержать только адрес; при отсутствии порта назначения используется 56000, как в upstream. `port` — локальный SOCKS-порт (например, 9000), он не подставляется в адрес VPS. Явный порт внутри `peer` сохраняется. Импортируются пароль, название и хэши; несколько хэшей дают отдельные варианты подключения. Число транспортных worker остаётся равным двум, независимо от `workers=9` в чужой ссылке. Настраиваемый порт вручную и ранее сохранённые явные порты не мигрируются автоматически.

OpenFlux v1: распознаются переносы строк, пробелы, URL-safe/обычный base64 и padding, как в upstream `share.Decode`. Из стандартной ссылки с несколькими транспортами извлекается Cups.online. Остальные транспорты, включая direct, не запускаются и не импортируются в маршруты. Контекст KDF берётся из исходного профиля либо определяется по правилам OpenFlux до удаления остальных транспортов. URL документа в таком случае используется только как соль KDF: приложение не обращается к документу. Пустой/отсутствующий контекст без документов соответствует upstream `http://#`. Незашифрованные, stream и неподдерживаемые codec-профили отклоняются.

Тестовые ссылки и все ключи в исходниках — синтетические. Присланная пользователем ссылка не публикуется и не используется для подключения к её серверу.

## Управление подключениями

Свайп карточки в любую сторону открывает подтверждение. Отмена сохраняет подключение. Удаление активного подключения сначала останавливает маршрут, затем удаляет профиль, выбранный ID и его секреты. Другие профили и их секреты сохраняются. При удалении последнего профиля он не создаётся заново при следующем запуске. Прямой маршрут автоматически не выбирается. Для доступности жесту соответствует действие «Удалить подключение».

По явному запросу пользователя удалён FLAG_SECURE на экранах сетевых настроек, диагностики, мастера, подготовки сервера и VK. Маскирование паролей в полях сохранено; ограничения на скриншоты, задаваемые самой ОС, приложение не меняет.

## Автоматическая подготовка из приложения

Администратор открывает «Подготовить мой сервер» и сразу попадает в форму VPS. Экспорт ZIP доступен отдельно по кнопке «Комплект для компьютера». Указывает IP/DNS, SSH-порт, сверяет SHA256-отпечаток с панелью VPS и вводит пароль root. Получение отпечатка выполняется без аутентификации и не считается подтверждением его подлинности. При изменении адреса/порта подтверждение сбрасывается. Пароль не сохраняется в настройках, Bundle, исходниках или журналах.

После явного запуска приложение проверяет встроенный ZIP и хэши выбранных файлов, Debian/x86_64/root и свободное место, передаёт ядра по SFTP, устанавливает локальную службу допуска и проверяет готовность. Есть прогресс, таймауты и отмена с закрытием SSH. Передача пароля происходит после проверки серверного SSH-ключа. Это прямое административное соединение, показанное в форме, а не новый маршрут для сообщений.

CLI и Android используют общий `deploy/remote-admission.sh`. Установщик проверяет хэши, сериализует установку через flock, сохраняет прежний бинарный файл/службу и выполняет откат при ошибке или прерывании транзакции. Уже выполненная подготовка может сохраниться после отмены; повторный запуск допустим.

**Подготовка не активирует VK/Cups и не открывает их слушающие порты.** Связывание допуска устройств с рабочими каналами, завершённый автодеплой транспорта, panchan-активация, полное парольное хранилище и две редакции остаются незавершённой частью проекта. Наличие административной службы само по себе не защищает legacy-выход.

## Сборка и зависимости

Для сборки из Git сначала создайте встроенный комплект:

```sh
python3 tools/network-native/prepare-deployer.py --rebuild
./gradlew :app:assembleRelease :app:assembleDebug :wear:assembleDebug testDebugUnitTest lintDebug clientRewriteContractTest
./gradlew -PnetworkUiTests=true :app:testDebugUnitTest --tests '*NetworkWorkspaceButtonsTest' --tests '*NetworkSettingsColdStartTest' --tests '*NetworkWorkspaceVisualTest' --tests '*MessagesListFollowTest'
python3 -m unittest discover -s deploy/tests -v
```

Зафиксирован SSH-клиент `com.github.mwiede:jsch:2.28.8`, с контрольными суммами и dependency locks. Лицензии BSD/ISC сохранены в `third_party/network/jsch`. Для Ed25519 используется встроенный BC verifier, доступный на Android10. В приложении не используются опциональные Windows-агенты, Kerberos, Unix-agent или сторонние logging backends библиотеки; исключения R8 ограничены их отсутствующими классами. Основные источники: [JSch](https://github.com/mwiede/jsch/tree/jsch-2.28.8), локальные закреплённые исходники qWDTT/OpenFlux.

Обязательные физические и живые проверки Tor/VK/Cups/обмена со стоковым Bitchat остаются в общем отчёте проекта. Успешная сборка не заменяет их и не означает чистый lint. Новый этап не проходил повторный обзор Astra.

## Результаты проверки комплекта

- Общая сборка release/debug/Wear, контрактные проверки: успешно. JVM приложения: 956 тестов, без падений/ошибок, 4 пропущены (включая opt-in VPS-тест). Wear: 245 без падений/ошибок.
- Финальная сборка после правок навигации, клавиатуры пароля и идентичности свайп-карточек: успешно; все 18 UI-тестов без падений/ошибок. Проверены жест, подтверждение/отмена, сохранение соседнего профиля, форма SSH и ограничения кнопок.
- 6 unit tests подготовки из Android входят в общий набор. Дополнительно opt-in SSH-путь с BC-криптографией проверен на разрешённом VPS: получение отпечатка, отказ неверного pin, передача файлов, установка и проверка службы.
- Общий установщик проверен с заведомо неработающим бинарным файлом: отказ, восстановление предыдущего релиза и готовность службы после отката.
- CLI: 7 unit tests без падений; синтаксис Bash проверен.
- Все пять APK подписаны тем же отдельным тестовым ключом; проверены версия46, minSdk29, отсутствие debug-флага, ZIP alignment, все четыре нативных компонента для ABI и вложенный комплект с его хэшами.
- Lint остаётся не чистым: приложение 303 ошибки / 412 предупреждений, Wear 37 / 52. В новых пакетах deploy/import и сетевого интерфейса ошибок нет.
- Подключения к VK/Cups по присланной ссылке не выполнялись. Живую передачу со стоковым приложением, Android10 на физическом устройстве и GrapheneOS ещё требуется проверить.
