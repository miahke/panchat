# Серверный комплект: qWDTT WG/Raw

Актуальный выпуск содержит qWDTT и локальную службу допуска. Cups/OpenFlux удалён по запросу пользователя. Tor obfs4/WebTunnel работает на клиенте и использует пользовательские мосты.

Требуется Debian x86_64, доступ root либо заранее настроенный sudo без пароля, TUN для серверных WG/Raw и свободное место. Комплект содержит готовые серверные бинарные файлы, GPL3, уведомления зависимостей и соответствующие исходники. Собственная пересборка: `python3 tools/network-native/prepare-deployer.py --rebuild`.

Мастер Android принимает IP/DNS, SSH-порт, логин, пароль либо выбранный приватный ключ с passphrase. Перед входом необходимо сверить SHA256 host pin. Для компьютера используется `deploy/wizard.py`; подробности и параметры приведены в `deploy/README.md`. Реквизиты владельца не включаются в исходники/ZIP.

Стандартные транспортные порты qWDTT: DTLS/WRAP 56000, RTP AEAD 56002, Raw v2 56003. Raw v2 требует совместимый сервер из этого комплекта; plaintext/старый Raw автоматически не включается. Клиент обращается к выходу через VK TURN; SOCKS слушает только loopback и требует пароль. Автоматического прямого fallback нет. Идентичности и форматы сообщений Bitchat не меняются.

Автоматический мастер размещает проверенный qWDTT, устанавливает Unix-only службу допуска и запускает WG/Raw. Нужны Debian x86_64, root либо sudo без пароля и TUN. Слушатели транспорта: UDP 56000, 56002, 56003. Административный HTTPS API слушает только 127.0.0.1:56443; приложение обращается к нему внутри проверенного SSH-сеанса. Публичный порт панели не открывается. Ключи владельца и API генерируются на сервере и сохраняются при повторной установке. База подписок находится в /var/lib/panchan/qwdtt, закрытые реквизиты — в /etc/panchan/qwdtt.

В приложении: «Настройки мода» → «Мой сервер и подписки». После проверки SSH-отпечатка выберите установку или управление подписками. Можно выдать qwdtt:// ключ с хэшем VK, сроком и лимитом устройств, продлить, отключить, включить или удалить доступ. SSH-пароль в ключ не входит. API-доступ приложения закрывается при уходе с экрана. Локальные настройки туннеля (WG/Raw, TCP/UDP TURN, автоматический транспорт, DNS/DoH, MTU, таймауты и keepalive) доступны в редакторе подключения; два worker используются независимо от количества сообщений.

Аппаратная привязка и отдельный пароль на всё хранилище не входят в текущий продукт. Доступ управляется подписками qWDTT, сроками, лимитом устройств и отзывом ключей. Существующий лимит устройств не является аппаратной аттестацией.
