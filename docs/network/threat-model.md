# Границы защиты и матрица последующих испытаний

Защищаем приватное содержимое сообщений и медиа, Noise/Nostr-ключи, пароли прокси и VPS, VK access token, ключ OpenFlux и строки мостов. Транспортный модуль получает уже сформированный сетевой поток; он не получает ключи шифрования сообщений Bitchat. Криптографические wire formats Bitchat не изменены.

TLS остаётся между приложением и Nostr-релеем; не завершается на VPS. Публичные каналы публичны, а VPS может наблюдать адреса/время/объём соединений. VK/Cups не становятся Tor и не дают анонимность Tor. Первичное подключение к VK/Cups и вход VK используют отдельные клиенты для предотвращения петли прокси; адреса этих сервисов могут разрешаться вне туннеля.

Сохранённые секреты шифруются AES-256-GCM с Android Keystore и привязкой к имени записи через AAD. Backup и перенос данных запрещены штатными deny-by-default правилами. WebView входа временно использует собственные cookies/DOM storage в закрытом хранилище Android; они очищаются при завершении Activity. Это отдельная граница: временные WebView-файлы не являются Keystore-записями. После аварийного завершения процесса остаточные WebView-файлы требуют отдельной проверки. Долгоживущий VK token сохраняется только в encrypted secret store.

Нативные Go-компоненты — PIE-процессы из установленного APK; JSON-конфигурация передаётся через stdin, а не argv. По stdout принимается ограниченный статус; сырые логи и токены не показываются. qWDTT-профиль и Chromium WebView не должны попадать в выгружаемые отчёты. Включение ошибок native/JNI, память процесса и дампы требуют отдельного анализа.

Пройденные автоматические проверки следует читать в итоговом отчёте, а не считать аудит уже завершённым. Обязательные последующие испытания:

| Область | Негативные сценарии | Ожидаемое поведение |
|---|---|---|
| Маршрутизация | остановка процесса, переключение во время WebSocket, занятый порт, потеря сети | закрытие старых клиентов, отсутствие прямого fallback |
| SOCKS | неверный пароль, подмена метода auth, короткие/фрагментированные пакеты | отказ без открытия соединения назначения |
| TLS | недоверенный сертификат, неверный SAN, downgrade на plaintext | отказ; имя релея передаётся в SOCKS без локального DNS |
| Содержимое | изменение ciphertext, replay, подмена отправителя, downgrade приватных медиа | отказ проверки подлинности, сохранение штатной политики Bitchat |
| OAuth | чужой redirect, несовпавший/повторный state, lookalike host, SSL error | token не принимается; нет JavaScript bridge/SSL bypass |
| Хранение | перенос ciphertext между записями, повреждение, backup, logout, panic | AEAD-отказ; секреты удалены; ошибка wipe видима |
| JNI/Go | oversized JSON/bridge line/frame, crash, cancellation, packet flood | ограничение ввода, завершение процессов, fail closed |
| Сервер | неправильный пароль/ключ, попытка управления с WAN, restart, replay | отказ; управление закрыто; защищённый транспорт восстанавливается |
| Устройства | Android 10, Android 17 GrapheneOS, экран выключен, перезапуск | корректный lifecycle без root/VPN; нет доступа к реальным координатам в тестах |

Ни эта таблица, ни один просмотр кода не являются доказательством отсутствия уязвимостей. По последнему указанию пользователя выполняется ровно один обзор GPT-6 Astra; исправления проверяет основной исполнитель. Публикация и работа на реальном VPS не разрешаются автоматически этими документами.
